# Contributing

Thanks for your interest in HIF.

## Before submitting
- Open an issue for large changes or architectural proposals.
- Keep provider-specific behavior inside adapters.
- Add tests for routing, retries, budgets and cancellation.
- Never add real API keys, personal data or customer prompts.
- Document new configuration fields and defaults.

## Pull requests
- Explain the user problem and design.
- Include tests and update docs.
- Keep changes focused and backward compatible where possible.
